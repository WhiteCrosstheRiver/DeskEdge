# 1.3 窗口网格与浅色卡片

日期：2026-10-04。用户选择接近 Windows 11 的浅色卡片。

## 外观

默认 `card_style: true`。区域、侧栏和启动器采用稳定的浅灰白卡片，减少壁纸色块的干扰；使用 12 DIP 圆角、单层细边框、轻标题分隔、淡蓝选中框，以及左右对称的图标布局。输入框与未选中复选框保留轻边框，避免与底色混在一起。

主题切换仍然可用，深色主题对应深灰卡片。“简洁卡片材质”关闭后恢复壁纸玻璃和浓度控制；卡片开启时禁用玻璃浓度，并说明切换方法。原生 Shell 图标、高分辨率提取和快捷方式箭头继续保留。

## 区域占位

默认 `window_grid: true`。位置、宽度和展开高度采用 24 DIP 网格，参考原点为每个显示器的工作区左上角。移动、右下角缩放和绘制新区域使用同一坐标计算。工作区边界不是整格时，选择内部的有效格点，使整张卡片留在工作区内。

拖动经过系统阈值后显示附近格点、边缘辅助线和尺寸提示。与其他区域的展开占位相撞或间距不足一格时显示红色提示；松手还原原位置。折叠保留原有 34 DIP 标题高度，仍为展开内容预留完整占位。拖动期间不保存模型，释放时只提交一次；Esc、取消或鼠标捕获丢失还原原布局。

首次升级将旧尺寸向上对齐，避免先缩小内容空间；接近的边缘对齐，并为相邻区域选择较近的空位。迁移标记防止以后反复自动整理。用户关闭窗口吸附后可以自由移动；重新开启时再次对齐。图标占位与区域占位分别设置。

辅助层使用本程序的 DirectComposition 窗口，不注册文件投放目标、不激活、不接管源窗口的鼠标捕获。窗口位于区域附近，缓存并复用绘制表面；不分配整个显示器大小的辅助层。显示器 DPI 改变时保持区域的逻辑尺寸；物理多显示器间拖动仍需实际使用验证。

## 验证

- 核心 51 项通过：包含窗口默认吸附、尺寸与坐标、非整格边界、一格间距、旧布局迁移、保存重载与关闭吸附，以及原有图标网格和文件操作检查。
- 原生桌面界面套件 114 项通过，0 失败：在真实桌面子窗口上检查 125% DPI 拖动和缩放、捕获与焦点、辅助层拒绝命中与激活、共享桌面宿主、保存重载、取消还原、工作区边界、占位冲突与新区域对齐。原有 Shell 文件菜单、复制、移动、链接、剪贴板和重命名检查继续通过。
- 辅助层自身 GPU 纹理检查确认背景 Alpha 为 0，目标填充 Alpha 小于 64，且表面尺寸小于全显示器。截图查看器可能将透明 PNG 显示为黑底或显示其原始颜色，不能据此推断实际桌面上的透明度。
- 检查了自有渲染预览中的区域、设置和图标落位。此类 PNG 是应用渲染目标，未替代资源管理器鼠标端到端测试或系统合成截图。

逐项结果：`evidence/core-test.txt`、`evidence/ui-test.json`。预览：`previews/projects.png`、`previews/grid-occupied.png`、`previews/window-grid.png`。

ctest --test-dir build -C Release --output-on-failure

原生界面套件会临时挂接桌面并操作独立目录中的自有测试文件。应先退出正常 DeskEdge 实例，使用全新的配置目录；退出后恢复桌面图标。
